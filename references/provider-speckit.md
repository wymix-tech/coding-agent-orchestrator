# SPECKIT native execution

## Enter when

The current Work selects `speckit`. Read only this Provider guide and the installed native instructions required for the current action.

## Execute

existing-behavior bugs may use `speckit-bug-assess` → `speckit-bug-fix` → `speckit-bug-test` only if the extension is installed. Bind assessment scope and explicit expected behavior; do not auto-install. New features use installed specify/plan/tasks/implement Skills, keeping required `plan.md` and `tasks.md` concise, and converge where supported. `specify implement` is not a terminal workflow command. Native prerequisites still apply even when CAO light has no plan-registration gate.

Finish tasks across ALL associated features before formal verification, even on light. Default tasks beside the current feature are captured automatically; add split features using repeated `cao sdd plan bind --plan <native-task-file>`. Keep quality checklists separate from implementation tasks; do not use a global feature list to certify this requirement. Preserve task IDs and file associations. Installed Skills define required planning, implementation and review order.

## Exit when

Current requirement tasks and applicable pre-verification obligations are complete; follow completion guidance and the native order for any remaining Commit/close steps. Standard/comprehensive retain workflow registration and independent final acceptance; light still honors native prerequisites.

## If blocked

Inspect `native_sync` diagnostics and associate the actual source. Source sync does not refresh acceptance hashes: review changed SPEC/criteria, explicitly rebind if needed, and reverify. Never invent entrypoints, reports or historical execution.

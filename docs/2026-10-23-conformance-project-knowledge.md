# CAO 过程符合性与项目知识实施记录

基线：main `194667c`（已合并 PR #19）。工作分支：`feat/conformance-project-knowledge`。

## 已实现

- `conformance show/check` 从现有生命周期、路由和产物要求生成带版本与指纹的要求清单，输出所有者、来源、状态、阻塞原因及修复方向。完成判断使用同一来源的证据。
- BMAD 的有效原生实现评审满足 `implementation_review`；有效规格审批和对应设计产物满足相应需求/设计门禁。其他专项要求、验证及需求验收仍按原契约执行。没有增加第二轮 CAO 功能代码评审。
- 统一冻结意图解析，拒绝缺失、未闭合、重复、嵌套和空标签。冻结块外的日志不再进入意图指纹；真正的输入及证据变化仍会使评审失效。
- `sdd review prepare` 检查仓库内代理定义与适配器能力，提前生成全部层票据、派发包及报告骨架；支持独立外部会话交接。成功 attach 后填入实际观察到的身份；子会话不能重建票据。
- `sdd review import` 复用原生校验器接收已有结构化报告。当前有效的已通过层不会被再次派发；全部完成时返回 `already_satisfied`。
- 报告和会话错误提供字段诊断。相同请求、会话、报告和状态连续失败时提供稳定修复标识及暂停重试信号。
- 原生评审完成和任务关闭后增量采集项目知识。记录来源哈希、作用域、事实/推断权限和来源 Work；冲突及过期知识不进入活动上下文。外部摘要保持 Work 范围的候选，不生成用户授权。
- 知识持久化使用原子快照和现有仓库锁。失败记录 pending，不撤销任务完成；refresh 或下一 Work 启动可重试。知识与运行文件不污染产品快照。可用 `knowledge.enabled: false` 关闭。
- 保留旧 CLI 入口和 Work 进度；补充按需参考文档、中英文说明及安装包资源检查。

## 验证范围

针对性用例覆盖缺失冻结闭合标签、日志追加不撤销审批、无 shell 的能力预检、分层交接/导入/解决、部分层通过后的恢复、过期代码证据、子会话禁止 restart、稳定重试诊断、空产物、知识来源失效、推断不得生成授权、并发写入、三方冲突、损坏记录及实际 done 后非阻塞恢复。

Pi 适配器测试使用真实适配器代码和测试宿主事件；Python 交接测试使用真实 CLI 和模拟宿主事件。它们不等价于真实模型在 Pi 主会话和子会话中完成原生评审。该环境验收仍需实际 Pi/provider 运行环境，不能据此宣称方案阶段 D 的真实模型端到端验收已完成。

## 首版边界

- 各 provider 继续使用其现有生命周期契约；本次明确的原生评审映射和批量派发针对 BMAD。不会给 OpenSpec 或 Spec Kit 硬套 BMAD 层级。
- 导入要求原有执行绑定和当前有效证据；缺乏真实性依据的历史结果不会被补造身份或升级为通过。
- `pause_retry` 是提供给编排者的停止信号，不能阻止模型忽略指令后继续调用。
- 知识提取为确定性最小闭环，尚不包含通用架构推断、环境经验挖掘或自动批准候选。旧记录不会被无依据地提升为项目规则。
- 知识使用单一原子 store，而非多文件记录加独立索引，避免跨文件提交的不一致。

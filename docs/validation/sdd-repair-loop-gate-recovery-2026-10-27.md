# SDD 实现循环与 CAO 门禁恢复验证

基于 main `f259a41190d99933ab89531dde3c2991e70059ad` 修复。

## 问题与边界

原生构建将 `src/main/resources/application.yml` 复制到已声明的
`target/classes/application.yml` 后，输出目录校验把 YAML 副本判为受保护输入。
Pi 在判断工具是否只读之前计算证据，错误进一步封死状态查询和父代理通信。
编译错误本身没有触发 CAO 验收；出错的是贯穿执行过程的快照/工具门禁。

SDD 完成前，构建、测试、修复、原生评审和验收继续属于 SDD 实现阶段。
失败可以阻止完成，不能阻止合法的修复和重测。CAO 继续保护派生状态和审批，
在原生义务完成后检查证据链，再执行项目基线，不重复业务代码评审。

## 修改

- 对已声明输出树中、存在相应构建清单的 Maven/Gradle 标准资源输出进行识别，
  支持根项目及子模块。真实资源源文件仍被快照覆盖，过滤后的副本、未重建的旧副本、
  删除源文件后等待 clean 的常规配置副本不使验证标准失效。
- 不接受任意未对应源码文件、已跟踪输出、符号链接、显式规则或验证输入被隐藏。
- 在证据刷新前判定明确的只读工具、父代理通信、子任务状态查询和 CAO 自身命令。
  CAO 命令继续执行其各自的状态转换门禁，未知命令和业务写入不因此获得豁免。
- Pi 后端不可用时，支持当前适配器自带的绝对 launcher 执行有限恢复命令，
  支持有限父代理通信和状态查询；不信任任意同名文件，不接受串联、重定向或命令替换。
- `cao status` 在快照范围故障下返回保存状态和 `inspection_only` 诊断，
  不声称旧证据仍然有效，不通过状态查询推动验收。
- 原生任务提示要求继续 SDD 检查失败后的修复循环，完成原生评审、验收和关闭义务；
  子代理提示要求承接当前步骤，不重新登记协调者的工作流执行。

## 回归方法

验证结果：

- Python 全量回归：94 个测试模块独立进程执行，合计 1,140 项通过，0 失败。
- `npm run test:pi`：39 项通过，0 失败。
- `npm run check:pi`：TypeScript 类型检查通过。
- `python -m compileall -q scripts tests`、`git diff --check`：通过。

`tests/test_sdd_repair_loop.py` 使用真实 CLI 与 Pi host-event，配合既有 BMAD
原生工作流夹具；本地检查程序实际复制 JVM 资源并编译故意有语法错误的 Python 文件。
检查失败后，主/子代理门禁允许修改和重测；重测成功仍保持 CAO implementation，
未产生 CAO verification 或 completion evidence，提前 verify 仍被 conformance 阻止。
故意放入不应隐藏的源码后，诊断/通信仍可达，业务写入仍被阻止。

快照测试覆盖 Maven、Gradle、测试资源、嵌套模块、资源变化、陈旧副本、删除源文件、
Git 跟踪冲突和显式规则保护。Pi 测试覆盖可信绝对 launcher、伪造 launcher、
命令注入/重定向、通信和状态查询边界，以及有效 deny 不被离线豁免覆盖。

本次没有运行真实 Maven/Spring Boot 构建或新的交互式 Pi/BMAD 全流程；
这些回归证明工具授权、快照和生命周期边界，不替代 SDD 对登录业务的实现与验收。

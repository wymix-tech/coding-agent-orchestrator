# demo2 实验：CAO 项目内使用问题修复方案

基线：main `be7b51254f3e92d6fe76681176c0bbae72208147`。

## 范围

仅调整 CAO 启动、调用识别、批准、原生评审证据、验证前置条件与交接恢复。
不修改 demo2 登录实现、测试、安全扫描或独立验收执行器。

## 设计与验收

| 问题 | 修复 | 验收 |
| --- | --- | --- |
| 安装前后重复询问技术栈 | 新项目先选 SDD、安装并重启，再恢复原始需求、一次性询问未知技术栈；host 自动保存首条未登记需求，Work 创建后标为已消费 | 第一会话仅提示 provider；真实重启后 bootstrap 可取得原始请求；子会话、重复提示不覆盖原请求；已确认的用户输入不被丢弃 |
| 验证基线不接受问卷回答 | 与 SPEC 共享绑定问题及提取回答逻辑，仍校验 Work、session、请求及当前基线摘要 | 当前问卷批准可 reanchor；旧问题、旧摘要、其他 Work/会话和子代理不得批准；存在两个请求时不猜测普通“批准” |
| 旧评审结果换票复用 | begin 返回独立会话启动命令；新独立 host session 在评审前 attach，绑定票据、模型和冻结输入；classify/submit 要求这份绑定 | 主会话、票据前已存在会话、旧票、变更快照、模型不符、未 attach 的报告被拒绝；真实新会话的匹配报告通过 |
| 评审协议错误或出现过晚 | 按 dispatch/oneshot 返回各自协议；执行阶段即路由评审参考文档 | dispatch 提示 JSON/classify/resolve，不提示旧 submit 协议；oneshot 保持 Markdown/submit |
| 安全验证能力发现过晚 | 路径评估后导航立即转到缺失的安全验证配置；实现守卫执行同一检查 | security 风险缺能力时，next/bootstrap 给出配置动作；原生规划和验证脚手架仍可写；配置并审核后恢复原 Work |
| 相对 launcher 被误拦截 | 以命令实际 cwd 和字面 cd 解析路径，仅豁免当前安装的真实 launcher | 相对路径与绝对路径等效；同名伪脚本、混合产品写入、输出重定向仍被拒绝 |
| 交接未表达当前等待 | 保存实时计算的 next_action，将待执行动作补充到 pending | 等待批准时 handoff 显示 human、当前请求与恢复命令；不重复生成相同交接 |

## 兼容与边界

- 新启动记录是 CAO 派生状态，只通过 host/CLI 更新，不由模型手工写入。
- 老 Work 和已确认决策不重新 intake，不因升级回退执行阶段。
- 缺少独立执行绑定的旧评审不能继续认证当前代码，需重新独立评审。
- attach 使用当前 host 的原生 session，不能在主会话代替评审者执行；没有子代理时使用新的独立 host 会话。
- 模型提供的报告仍是语义判断；CAO 只核对执行身份、输入一致性和原生协议，不声称证明评审质量。
- 运行针对性回归、完整 Python unittest、编译检查以及现有 Pi adapter 测试。

## Root causes and resulting behavior

1. **P1 — source omitted by directory name.** All depths named build/dist/target
   were skipped. These names now have no automatic exclusion. Untracked inputs
   are scanned regardless of `.gitignore`; indexed files override cache and
   explicit user pruning. Unrelated dependency subtrees remain pruned when a
   specific indexed file lives inside a cache tree.
2. **P1 — Pi bridge failures permitted effects.** Transport failure produced only
   a diagnostic and no deny. Enrolled/unknown projects now block writes, patches,
   unknown tools and arbitrary shell on missing decisions. Normal allow/deny
   remains authoritative. Offline recovery uses exact command strings and known
   read tools, with no arbitrary shell parser or retry. The 8-second bridge
   deadline leaves headroom over the 5-second lock wait; the model sees concrete
   recovery steps and a real lock error remains distinguishable from a timeout.
3. **P2 — generated reports invalidated successful checks.** Unregistered output
   was indistinguishable from source. Exact output declarations now participate
   in the accepted verification/snapshot digest before execution. Only those
   paths are omitted; concurrent source changes still produce stale evidence.

## Configuration and migration

```sh
# Preserve existing scripts; replace the output list with these two declarations.
cao verification configure --replace --output coverage.xml --output reports/

# Explicit build/cache scope, preserving scripts and the existing output list.
cao verification configure --replace --exclude-path build/ --exclude-path dist/

# Existing active Work: review changed acceptance and follow any human approval first.
cao reopen --reanchor --reason "Reviewed snapshot v4 scope and report outputs"
cao verify
```

`--clear-outputs --replace` and `--clear-exclude-paths --replace` clear their
respective lists. No option silently clears the other list or script commands.
Path declarations are rooted at the project: a trailing slash covers a subtree,
otherwise only that file is covered. Globs, absolute/traversing paths, root-wide
scope, symlink declarations and protected source/wrapper/manifest paths are
rejected. Report output trees also reject source-like files and indexed inputs.
Use the dedicated reference guide for complete matching and recovery rules.

Earlier records remain readable. v3 verification results and review snapshots
are not reusable as v4 evidence. Do not modify derived Work JSON to migrate;
review/reanchor active work and refresh native review/acceptance where required.
A commit of an already-scanned product file alone does not change its snapshot,
but newly indexing a previously pruned cache file adds an input and correctly
invalidates old evidence. Do not commit generated bytecode to avoid that change.

## Bounded performance comparison

Same Linux host, 1000 source files of 1KiB each, one 64MiB data file, 2000 ignored
dependency files of 1KiB each. Five warm calls per case; median wall time and a
separate `tracemalloc` Python-allocation peak. The baseline is the snapshot
implementation from `14688e0` with its original ignore set. These are local
measurements under shared load, not production capacity or RSS measurements.

| Project | Baseline median | Fixed median | Baseline peak | Fixed peak |
| --- | ---: | ---: | ---: | ---: |
| Non-Git | 141.29ms | 126.82ms | 64.01MiB | 2.07MiB |
| Git, 1001 indexed inputs | 139.65ms | 130.10ms | 64.01MiB | 2.18MiB |

Git index discovery and scope guards did not cause a material regression in this
scenario. Streaming avoids reading the full large file into a single Python
bytes object. The native acceptance input path also avoids its prior redundant
second source scan.

## Limits and rollback

- Adapter tests invoke registered Pi handlers with fixture contexts and the real Python core; no live model session or external SDD runtime was used.
- Only Linux was executed here. Type checking is cross-platform; macOS/Windows
  process cleanup and case behavior still need the existing platform CI. POSIX
  process-group cleanup was tested with a real child PID.
- Offline enrollment is an in-memory guard after observing project state. A
  genuinely uninitialized project is distinct; deleting all state and restarting
  loses that observation. The adapter is orchestration control, not OS isolation.
- Output declarations are intentionally conservative about source-like report
  assets. Explicit cache/build exclusions are trusted scope decisions and must
  not contain untracked product input.
- To inspect the prior code, use a separate worktree at `14688e0` after
  preserving the repair branch/worktree. To roll back a committed repair,
  revert that repair commit on a new branch. Runtime evidence should be reviewed/reanchored under the selected
  algorithm; never restore stale evidence by editing format numbers or Work JSON.

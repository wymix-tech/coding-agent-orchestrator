# Contributing

Thanks for helping improve Coding Agent Orchestrator (CAO).

## Development setup

Install the CLI in editable mode so `cao` uses the checkout:

```bash
python -m pip install -e .
cao --help
```


CAO's core and test suite use the Python standard library. Python 3.10 or newer is required. The integration tests also use Git and create temporary repositories; they do not require a real SDD installation or network access.

## Run checks

```bash
make check
make test
```

Equivalent test command:

```bash
python -m unittest discover -s tests -v
```

## Change guidelines

- Keep the core agent-neutral. Host adapters should translate lifecycle events rather than duplicate work-state or verification rules.
- Keep SDD artifacts native. CAO should store references and execution continuity, not copies of SDD documents.
- Do not commit `.orchestrator/` runtime state (work items, index, sessions, and handoffs), generated bytecode, caches, secrets, or local environment files. The `.orchestrator/config.json` project configuration is intentionally trackable.
- Add regression tests for behavior changes, especially Work Item transitions, `index.json` synchronization, SDD installation, verification exit codes, and host hooks.
- Keep verification project-configurable. CAO executes the configured scripts and interprets their exit codes; it should not hard-code project coverage or test thresholds.

## Python module ownership

`scripts/cao.py` is a compatibility entry point. Add implementation to the owning
domain module described in [CAO module boundaries](docs/cao-module-structure.md),
and import that owner directly in new code. Patch dependencies in their caller
modules when testing failures; facade exports retain the original function objects.
